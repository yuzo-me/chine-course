# T-12. Внесение правок учителя

**День:** среда 11.11 (или как только пришли отметки) · **Разработчик:** Claude Code · **Ревью:** Codex · **Время:** 1–2 ч

## Зачем
Контент на показе должен быть проверен учителем — это главный аргумент качества.

## Входные данные
CSV от учителя (`id, hanzi, field, comment`) → положить в `content/review/teacher-YYYY-MM-DD.csv`.

## Что сделать
1. `content/scripts/apply_review.py`: читает CSV → создаёт `content/data/hsk1.fixes.json` (исправления значений/пиньиня) и список слов для перегенерации аудио. Неоднозначный комментарий **не применять автоматически** — вывести списком владельцу.
2. Исправление пиньиня → проверка, что новый пиньинь валиден; перегенерация аудио этих слов.
3. `build.py` применяет `fixes` поверх данных; статусы: `fixed` для исправленных, `reviewed_ok` для остальных проверенных, `reviewedBy: "teacher"`, дата.
4. Отчёт: сколько ошибок нашёл учитель по типам, что исправлено, что требует уточнения.

## Критерии приёмки
1. Все однозначные правки применены; неоднозначные — в списке вопросов.
2. Исходные файлы (`raw`, `meanings`) не изменены — правки отдельным слоем.
3. Валидатор без ошибок.
4. Доля ошибок учителя записана в отчёт (это будет цифра для презентации: «учитель проверил 300 слов, исправлено N»).
