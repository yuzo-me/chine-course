# T-06. Озвучка слов и страница проверки для учителя

**День:** понедельник 9.11 · **Разработчик:** Claude Code · **Ревью:** Codex · **Время:** 2–3 ч
**Нужно заранее:** решение D-16 (сервис озвучки) и ключ API от владельца (если вариант А или Б).

## Зачем
Звучание слова нужно для запоминания тонов. Учитель должен быстро проверить все 300 слов.

## Что сделать
1. `content/scripts/generate_audio.py`:
   - для каждого слова — mp3 (моно, ~48–64 кбит/с) в `content/audio/<id>.mp3`;
   - через SSML **задавать произношение по пиньиню из данных**, чтобы избежать неверного чтения многозначных знаков;
   - ключ API — только из `.env.local`; повторный запуск не перегенерирует готовые файлы (кроме явного флага);
   - журнал: голос, сервис, дата → в отчёт и в `docs/08-лицензии.md`.
2. `build.py` добавляет путь `audio` в слова; валидатор проверяет наличие файлов.
3. Страница `/review` на сайте (не в нижнем меню, только по прямой ссылке):
   - таблица всех 300 слов: иероглифы, пиньинь, часть речи, значение, кнопка ▶;
   - для слова кнопка «Есть ошибка» → выбор (пиньинь / значение / звук) + поле «как правильно»;
   - отметки сохраняются в браузере (не теряются при перезагрузке);
   - кнопка «Скачать отметки» → CSV (`id, hanzi, field, comment`);
   - сначала показывать слова с низкой уверенностью и предупреждениями валидатора; фильтр «только непроверенные».
4. Слить в main к вечеру, чтобы страница была доступна по постоянной ссылке.

## Если сервис озвучки не готов
Временно — голос браузера (Web Speech API) только на странице проверки и в карточках, с пометкой в отчёте. Это запасной вариант, не основной.

## Критерии приёмки
1. 300 файлов, каждый проигрывается, длина 0,3–3 с.
2. Ключа API нет в репозитории (проверить поиском).
3. Страница `/review` работает на телефоне и компьютере; CSV скачивается и открывается в Excel/Numbers с корректной кодировкой (UTF-8 с BOM).
4. Отметки переживают перезагрузку страницы.
